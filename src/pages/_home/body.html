The server only stores ciphertext

Your browser encrypts with OpenPGP before anything is sent. The key travels in the link, in the part a browser never sends to a server. Yopass deletes the ciphertext on first read or when its time runs out.

Read the source on GitHub

Request a secret from anyone

  1. Create a secret request

    Your browser makes a key pair. The public key goes to the server and the private key never leaves your browser.

  2. Send the link for the secret

    Chat, email or a support ticket will do. The responder needs no account and installs nothing.

  3. Collect the secret once

    Their answer is encrypted in their browser and decrypted in yours. The server deletes it as you open it. Part of the business license.

Put sign-in before sharing

OpenID Connect with your own provider. Only signed-in users from your email domains create secrets.

OIDC_ISSUER=https://accounts.google.com
OIDC_CLIENT_ID=123456789-abc.apps.googleusercontent.com
OIDC_CLIENT_SECRET=GOCSPX-…
OIDC_REDIRECT_URL=https://yopass.example.com/auth/callback
OIDC_ALLOWED_DOMAINS=example.com
OIDC_REQUIRE_VERIFIED_EMAIL=true

Yopass runs on your own servers

Yopass is one Go server with Redis or Memcached behind it. Docker Compose starts both in under five minutes, and Kubernetes works as well. Secrets stay on infrastructure you control.

Can the Yopass server read a secret?

No. The browser encrypts it first. The server stores ciphertext and never receives the key.

What happens after a secret is opened?

A one-time secret is deleted on first read. Every other secret is deleted when its lifetime ends.

Does the recipient need a Yopass account?

No. They open the link in a browser.

Is there a hosted Yopass?

No. You run it on your own servers. The public demo is for trying it.

What does a license add to Yopass?

Secret requests, read receipts, webhooks, audit logging, OpenID Connect sign-in, theming and larger uploads.
